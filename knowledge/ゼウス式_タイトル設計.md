# title-guide — タイトルのカテゴリと、読者の段階との相性

> このシステムでの使いどころ: Phase 3 PART D（タイトル設計）・/title でタイトル案を作る時。
> 本文中の「工程」「◯◯シート」「`NN_◯◯.md`」は、元になった記事制作手順での呼び名。このシステムでは Phase 0〜5 の出力（`00a_self_analysis.md`〜`05_sales_letter.md`）に読み替える。「`assets/…`」「`scripts/…`」「`agents/…`」「`sales-kit/`」と書かれた道具・ひな形はこのシステムには無いので、その部分は目視で代用する。
> 文例・型のフレーズはそのまま本文に写さない。

目次: §1 11カテゴリ／§2 読者の段階×カテゴリ／§3 note でよく使われる15の型／§4 記事の部位と段階／§5 避ける5つ／§6 字数／§7 記録のしかた

## §1 11カテゴリ

1 逆説・常識破壊／2 秘密・暴露／3 権威・実績／4 悩み・共感／5 恐怖・危機感／6 ノウハウ・解決策／7 ストーリー・告白／8 問いかけ／9 対立・比較／10 断定・強い主張／11 ティザー・予告

10案を作る時は5カテゴリ以上から出す。同じカテゴリを3案続けて並べない。

## §2 読者の段階×カテゴリ

段階は `ゼウス式_読者設計.md` §3 の9段階。タイトルは、冒頭の主役の段階で引く。

| 段階 | 相性のよいカテゴリ | 気をつけること |
|---|---|---|
| 0〜2 気づいていない・なんか違う・しんどさを自覚 | 8 問いかけ／4 悩み・共感／1 逆説・常識破壊 | 6 ノウハウ・10 断定は、まだ問題を認めていない人には早い |
| 3〜4 自分のせいだと思う・正体が分からない | 1 逆説・常識破壊／9 対立・比較／7 ストーリー・告白 | 責める言い方にしない。5 恐怖・危機感は煽りにならない範囲で |
| 5〜6 原因が見えてきた・やり方を探す | 6 ノウハウ・解決策／10 断定・強い主張／9 対立・比較 | 手順が本文に無いのに「手順」と書かない |
| 7〜8 比べている・踏み出す直前 | 11 ティザー・予告／2 秘密・暴露／3 権威・実績 | 3 権威・実績は実績が事実として確かな時だけ |

## §3 note でよく使われる15の型

| 型 | 使う場面 | 避ける場面 |
|---|---|---|
| 完全攻略型 | 1つのテーマを入口から完了まで体系的に扱う | 範囲が狭く、答えが1つで終わる |
| 手順型 | 初心者が順番どおりにできる工程を示す | 分岐が多く、一方向の順番にできない |
| 秘訣公開型 | 実際の体験・検証から得た意外な知見を出す | 根拠になる体験・検証が無い |
| 比較型 | 複数の案を同じ物差しで選び分ける | 物差しが揃わない |
| 失敗回避型 | 事前に確認できる落とし穴と避け方を示す | 不安をあおるだけで、避け方を示せない |
| 体験記型 | 書き手の実際の体験と、変化の仕組みを扱う | 作り話・合成した人物・起きていない成果に頼る |
| チェックリスト型 | やる前・やった後に確かめる項目を並べる | 項目が曖昧で、確かめても結論が変わらない |
| 質問回答型 | 実際によく聞かれる疑問にまとめて答える | 質問を作る／質問どうしの対象がばらばら |
| ランキング型 | 共通の物差しで順位をつけられる | 物差しや観察したデータが無い |
| 総まとめ型 | 十分な一次情報を整理して結論を示す | 素材が薄いのに網羅に見せる |
| ノウハウ公開型 | 実際に使っている方法・資料・判断の基準を出す | 使った実績が無い |
| 時間の流れ型 | 実際の記録を期間ごとに比べる | 期間・変化・理由を確かめられない |
| 逆説型 | 通説と違う結論を、仕組みと証拠で示す | 根拠のない逆張りだけになる |
| 権威＋ノウハウ型 | 確かめられた経験量と、再現できる方法を同時に示す | 経験の年数・件数・実績を確かめられない |
| 共感＋解決型 | 実際のつまずきと、抜け出す条件を扱う | 悩み・解決・成果のどれかを作る |

## §4 記事の部位と段階

| 記事の部位 | 主役の段階 | 役割 |
|---|---|---|
| タイトル・冒頭 | 冒頭の段階（多くは0〜2） | 手を止めさせ、自分のことだと思わせる |
| 無料部分の後半・本編の前半 | 本編の段階（多くは3〜5） | 困りごとを代わりに言い、思い込みの原因を揺らし、本当の原因に名前を付ける |
| 本編の後半 | 本編の段階（多くは5〜6） | 具体的な手順と最初の1つを渡す |
| 最後の誘導 | 誘導の段階（7か8） | 迷いと不安に答え、小さな1つを選んでもらう |

## §5 避ける5つ

1. 抽象語だけで、対象・行動・判断が分からない（実在しない権威の数字で補わない）
2. 説明や定義の宣言から入り、読み手への主張が無い
3. 条件を重ねすぎて、当てはまるはずの読者まで入口で外してしまう
4. 同じ言葉・主張・言い回しを、短い入口と長い結論で繰り返す
5. 短くするために、不自然な造語や省略を作る

## §6 字数

note 公式の目安は `ゼウス式_note媒体仕様.md` §3 を正とする。案ごとに字数を書き添え、一覧で途中が切れても意味が通るかを目で確かめる。

## §7 記録のしかた（21_タイトル案.md）

| 番号 | 案文 | 字数 | カテゴリ | 書き方の意図 | 柱1 | 柱2 | 柱3 | 合計 |
|---|---|---|---|---|---|---|---|---|

柱1（断言力）と柱2（情景力）は `scripts/hook_score.py 21_タイトル案.md` で採点する。スクリプトはファイルを書き換えず、点数を入れた表を画面に出すので、その表を 21_タイトル案.md に写し、空欄で出てくる柱3と合計を書き込む（表には柱1の決め手になった語・柱2の要素の列が足される）。

- 柱1（0〜4点）: 4＝先頭12字に強い言い切りの語がある／3＝先頭12字に言い切りの語幹か、打ち明け話の入り口の語（ぶっちゃけ・正直に言うと など）がある／1＝「？」で終わる／0＝言い切りが無い、または説明から始まる（「〜について」「〜とは」など）
- 柱2（0〜3点）: 時刻・場所・体・固有名詞・数字のうち、入っている種類の数（3で頭打ち）。一般名詞のカタカナ（ダイエット・スマホ など）は固有名詞に数えない
- 表の「字数」は句読点を除いて数える。note の推奨字数と比べる時は、句読点を含めて自分で数え直す

柱1〜3の物差し（断言・情景・わかってくれ感、合計7点が目安）は、作者が SNS の1行目の強さを測るために作った採点表を元にしている。柱3（わかってくれ感・0〜3点）は、読者設計シートの本音と照らして自分で書き、理由を1行添える。合計（柱1＋柱2＋柱3）は並べ替えの目安で、選ぶのはユーザー。
