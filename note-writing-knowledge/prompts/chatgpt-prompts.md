# ChatGPT用プロンプト集

## 1. 初回ヒアリング

```text
これから、日本の個人発信者向けのマーケティング記事を設計します。

最初の返答では記事を書かないでください。
不足情報を埋めるため、次の項目を一問ずつ質問してください。
短い回答例も添えてください。

1. 誰に向けるか
2. その人が実際に経験している場面
3. 顧客の原文
4. 現在信じている原因
5. 読後に信じてほしい原因
6. 自分の経験
7. 根拠
8. 無料で渡すもの
9. 有料で支援する範囲
10. CTA
11. 媒体
12. 文字数

私が答えていない経験、顧客、数字は作らないでください。
```

## 2. 顧客の原文分析

```text
以下のDM、コメント、アンケート、相談メモを分析してください。
まだ記事を書かないでください。

目的は、顧客の言葉をきれいな用語へ変えることではなく、
具体的な生活場面、感情、自己評価、恐れている未来、欲しい許可を見つけることです。

出力：
1. 原文
2. 時間・場所・行動・相手・直前直後
3. 本人が明示した感情
4. 仮説の感情
5. 自己評価
6. 恐れている未来
7. 欲しい許可
8. 事実
9. 仮説
10. 追加質問
11. 今は断定しないこと
12. 記事冒頭の場面10案

原文にない病気、性格、家庭事情、トラウマを断定しないでください。
```

## 3. 教育5層

```text
前の顧客分析を使い、教育5層を作ってください。

1. 出来事
2. 感情
3. 自己評価
4. 恐れている未来
5. 欲しい許可

次に、
- 現在の自己解釈
- その解釈と矛盾する事実
- 新しい自己解釈
- 新しい解釈を支える仕組み
- 今日できる一歩
を作ってください。

不安を強めて売るのではなく、自己攻撃を弱め、
問題を生む構造と現実的な行動へつなげてください。
```

## 4. 主張設計

```text
以下の材料から、一記事一主張を決めてください。
本文はまだ書かないでください。

出力：
- 対象読者
- 読者が現在信じていること
- 読後に信じてほしいこと
- 中心主張
- 根拠3つ
- 反論5つ
- 自分の経験を入れる場所
- 顧客の原文を入れる場所
- 無料部分だけでできる一歩
- Offerへの橋
- CTA
- 書かないこと
```

## 5. 外部リサーチ

```text
次の主張について、外部確認が必要な事実だけを調査してください。

【主張】
{主張}

条件：
- 公式資料、一次情報、原著論文を優先
- 公開日・更新日・対象地域を確認
- 現在も有効か確認
- 賛成材料だけでなく、制限、反証、例外も探す
- 各情報を「確認できた事実」「言えないこと」「安全な表現」へ分ける
- 記事本文は書かず、出典メモを作る
- 出典不明の数字は採用しない
```

## 6. 新PASONA

```text
以下の顧客原文、教育5層、Offerを使い、
新PASONAで登録ページまたは販売文を設計してください。

P：具体的なProblem
A：感情と自己評価へのAffinity
S：新しい原因理解とSolution
O：実行を助けるOffer
N：向く人、向かない人、前提条件
A：一つのAction

禁止：
- 偽の締切・残数
- 本人が言っていない恐怖
- 架空の実績
- 購入しない人への人格攻撃
- 複数CTA

まず六要素の設計を出し、その後に完成原稿を書いてください。
```

## 7. 7日間リスト教育

```text
以下の無料特典を受け取った人へ、
7日間のメールまたはLINE教育を作ってください。

0日目：特典と最初の一歩
1日目：具体的な出来事
2日目：感情
3日目：自己評価の修正
4日目：恐れている未来を因果で説明
5日目：事例・小さな証拠
6日目：Offer、向く人、向かない人
7日目：一つのAction

各通について、
役割、読前の認識、読後の認識、件名5案、本文、CTA、返信質問、
使用した根拠、人間確認事項を出してください。

同じ販売文を繰り返さず、登録理由と一致させ、
配信停止と読者の選択権を守ってください。
```

## 8. 厳しい編集

```text
以下の原稿を、売り手に同調しない厳しい編集者として批評してください。

確認：
- 顧客の原文にない痛みを創作していないか
- 共感が一般論になっていないか
- 自己攻撃を増やしていないか
- 主張と根拠が対応しているか
- 相関を因果としていないか
- 自分の経験を一般化していないか
- 新PASONAが露骨な型になっていないか
- Offerの対象外が明確か
- CTAが一つか
- 未確認の最新情報、数字、法律がないか
- AIが好む曖昧な美辞麗句がないか

各問題について、
原文、問題、読者への影響、修正方針、修正文
を出してください。

最後に修正後全文と、人間が確認すべき点を出してください。
```

## 9. 自分にしかない経験を引き出す

```text
この記事に必要な、私にしか答えられない材料を引き出してください。

一問ずつ質問してください。
抽象的な感想ではなく、
時間、場所、相手、直前の出来事、実際に言った言葉、
失敗した判断、変えた判断、数字、証拠
が出るように掘り下げてください。

私が答えていない体験は作らないでください。
```

## 10. Skill化

```text
以下の成功した作業手順を、日本語のAgent Skillとして再利用できる形へ変えてください。

SKILL.mdに必ず含めるもの：
- name
- description
- 目的
- 使う場面
- 使わない場面
- 事前情報
- 作業手順
- 納品形式
- 品質基準
- 禁止事項
- 例外時の対応
- 入力例
- 出力例
- テスト観点

nameは英小文字・ハイフン区切り。
descriptionには、起動条件と除外条件を具体的に書く。
本文は、日本人の新人へ渡す業務手順書のように書く。
不足情報を推測しない。
外部送信、公開、課金、破壊的操作は、人間の承認条件を明記する。

完成後、Skillを小さく分けるべき箇所も提案してください。
```
