# Phase 7（任意）: SNS横展開（リパーパス）

## 概要

完成・承認済みの1本のコンテンツ（`04_paid_content.md` / `05_sales_letter.md`）を、
毎回ゼロから作らず、**媒体ごとに役割とCTAを変えて**横展開する。同じ文章の切り貼りはしない。

**位置づけ**: 6フェーズパイプラインの後に続く**任意**の追加機能。`/repurpose` または「SNSに展開して」で起動する。
**前提**: 元素材（04/05）が完成・ユーザー承認済みであること。未完成の下書きには使わない。

---

## 入力情報

- `output/05_sales_letter.md`（無料部分。中心主張の抽出元）
- `output/04_paid_content.md`（有料部分。実装・根拠の抽出元）
- `output/02_concept.md`（コンセプト・教育5層）
- どの媒体へ展開するか（起動時にユーザーへ確認。指定が無ければ以下の標準セットを提案）:
  - X長文 / X短文 / Threads / note（別記事） / メール / 無料PDF案内

---

## 実行手順

1. 元素材から**中心主張を一文**にする（ぶれさせない）
2. 使える顧客原文・経験・根拠を洗い出す（`customer_voice.md`があれば優先）
3. 展開先の媒体ごとに「目的」を決める
4. 媒体ごとに冒頭を作る（同じ冒頭の使い回しをしない）
5. CTAを媒体ごとに一つ決める
6. 同一文章の機械的な貼り付けを避ける（要約・再構成する）
7. 匿名化・事実・引用を再確認する（fact-ethics-check原則）
8. 投稿前の確認事項を出す（このプロンプトは投稿を自動実行しない）

---

## 媒体ごとの役割（デフォルト定義）

```
X長文    : 問題認識と新しい解釈（教育5層①〜③が中心）
X短文    : 一つの場面、または一つの主張
Threads  : 気づきを会話的に展開
note     : 背景・根拠・反論・実装（別記事として。今回のnote本体とは別に切り出す場合）
メール    : 一通一認識変化（06_list_sequence.mdと連携可）
無料PDF案内: 最初の完了体験への導線
```

---

```markdown
## 確認事項（人間の最終確認）

- [ ] 中心主張が媒体を通してぶれていないか
- [ ] 各媒体でCTAが一つに絞られているか
- [ ] 同じ文章の切り貼りになっていないか（媒体の受け取り方に合わせて再構成したか）
- [ ] 匿名化・事実確認ができているか
```

---

## 執筆ルール

| ルール | 詳細 |
|--------|------|
| 中心主張の一貫性 | 媒体が変わっても主張はぶれない |
| 文体の切り替え | 媒体ごとに文体・文字数を合わせる（Xは短文、noteは長文等） |
| CTA | 媒体ごとに一つ |
| 誇張禁止 | 「絶対」「誰でも」等の断定は使わない（CLAUDE.md 禁止ワード参照） |
| 自動投稿禁止 | このプロンプトは原稿作成までを担当する。**実際の投稿は必ず人間が行う**（noteのみ`post_to_note.py`による下書き投稿の対象） |
