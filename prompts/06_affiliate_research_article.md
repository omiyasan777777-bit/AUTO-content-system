# Phase A（アドオン）: アフィリエイト訴求型リサーチ記事

## これは何か

有料note構築の6フェーズパイプラインとは別に、**「○○を徹底リサーチしてジャンル別に記事化、アフィリエイトリンク付きで無料記事として出す」**という単発リクエストに応えるためのテンプレート。
2026年8月に「子供が無料で泊まれるホテル・旅館リサーチ記事」を作った際の構成・品質基準を標準形として固定したもの。

## トリガー

以下のようなリクエストが来たら、ヒアリングや6フェーズを経由せず、このテンプレートに従って直接記事を執筆する：
- 「〇〇を徹底リサーチして記事にして」
- 「〇〇（施設・サービス・商品など）をジャンル分けして紹介記事を作って」
- 「アフィリエイトリンクを貼って」「リンクを設置して」という指示を伴う施設・商品紹介系の依頼

Phase 0〜5の商品設計・セールスレター用ではなく、**それ単体で完結する無料の情報記事**として扱う。

## 保存先とファイル名

- 通常のワーキングフォルダ（`output/`, `output2/`...）の自動採番ルールに従う
- ファイル名は **`05_sales_letter.md`** に固定する（`post_to_note.py` がこのファイル名を読みに行くため。中身は本来のセールスレターではなく通常の記事だが、投稿フローに乗せるためこの名前を使う）
- `04_paid_content.md` は作らない（`post_to_note.py` 側で有料部分が無い場合に対応済み）

## 記事の構成（固定テンプレート）

1. **導入章**（h2 1つ）
   - フックとなる課題提起 → 記事で解決できることの提示
   - リサーチ対象の条件・期限（あれば）を明記
   - `> **※注意**` の引用ブロックで条件の変動・確認を促す注意書き
2. **タイプ別の選び方章**（h2 1つ、中に h3 で3〜5パターン）
   - 「自分にはどれが合うか」を読者のペルソナ別（家族構成・利用シーン等）に整理
   - 後続の各ジャンル章への橋渡しにする
3. **ジャンル別紹介章**（ジャンルごとに h2 1つ、施設ごとに h3）
   - 対象を意味のあるジャンルに分類する（例: コスパ重視／高級路線／アクセス重視／自然体験 等）
   - 各施設（h3）の中身は以下を全て含める：
     - 概要・強みの説明（**太字を多用**）
     - 追加の具体情報（アクセス・設備・価格帯など）をもう1段落
     - 可能な限り **実際の口コミを引用（`>` ブロック）** する。出典が明示できない場合は「（宿泊者の口コミより）」等サイト種別のみ表記し、捏造しない
     - **アフィリエイトリンク**を独立行で設置: `**[▶ 楽天トラベルで空室・料金をチェックする](<リンクURL>)**`
     - 「周辺の子供が楽しめる無料スポット」等、無料で楽しめる周辺情報を箇条書きで追加
4. **注意点章**（h2 1つ、番号付きリスト3〜5項目）
   - 条件のばらつき、リンク先の条件変動、予約時の入力ミス等、実利用で失敗しないための注意
5. **FAQ章**（h2 1つ、質問ごとに h3）
   - 4〜5問。条件の境界線・併用可否・期限後の扱いなど、読者が迷いそうな点を先回りする
6. **まとめ章**（h2 1つ）
   - 紹介した施設をジャンル別に箇条書きで再掲
   - 最後にもう一度アフィリエイトリンクへ誘導する一文で締める

## フォーマットルール（厳守）

- **1つの章にh2見出しは1つだけ**。それ以外の見出しは全てh3
- **太字を積極的に活用**（強調したい数字・条件・固有名詞）
- **引用（`>`）を実際に使う**。口コミが取得できる場合は必ず反映する
- **Markdownの表は使用しない**（noteが表非対応のため。比較は箇条書きで表現）
- 文字数は **8,000〜10,000字（空白・改行除く）** を目安にする。`python count_chars.py <ファイル>` で必ず実測する（`wc -m` 禁止）
- アフィリエイトリンクは紹介する対象（施設・商品）ごとに毎回設置する。ユーザーから別のリンクを指定されない限り、直近で指定されたリンクを既定値として使い回してよい

## タイトル

記事の内容が完成したら、**内容とは別に「魅力的なタイトル案」を提示**する。以下の要素を意識する：
- 意外性・お得感のフック（「まさかの0円」等）
- 期限や条件など具体性
- 「ジャンル別」「口コミ付き」等、情報の網羅性・信頼性を示す一言
- タイトルは記事本文（Markdown）には含めない（`post_to_note.py --title` で別途渡すため）

## note投稿

このアドオンで作った記事も、通常のnote投稿ルールに従う：
```
python post_to_note.py --dir {ワーキングフォルダ} --title "{提示したタイトル}" --profile "{accounts.jsonのcurrent}" --auto-save
```
ただし note.com への実際の投稿はローカル環境（Selenium + ログイン済みChromeプロファイル）でのみ実行可能。クラウド実行環境ではコマンドの提示までに留める。
